# Security

## How keys are handled

- **Hosted play needs no keys from visitors.** The deployment's keys are Cloudflare Worker secrets, and the page never receives one: it calls the Worker's `/api` routes and the Worker adds the key upstream. For Reactor, the Worker mints a short-lived token scoped to one session; the browser connects with it, and it reaches only that session. The Worker ends hosted sessions with its own key, scrubs its keys from any provider error it passes on, and logs nothing.
- **A pass for every hosted call.** Hosted routes are not a free API. On load the page runs an invisible Cloudflare Turnstile challenge, which a visitor never sees, and trades its token once at `/api/pass`: the Worker checks it with siteverify (single use, at most 300 seconds old, this hostname and action) and sets a 15-minute pass, an HttpOnly, Secure, SameSite=Strict cookie signed with its own HMAC secret and bound to the visitor's network. Every hosted route refuses a request without a valid pass, so a forged `Origin` gets nothing, and the page renews the pass silently before it expires. Play on your own keys needs no pass and loads no Turnstile.
- **Abuse limits.** Hosted routes answer only the site's own origin, rate limited per client address (an IPv6 address by its /64). Request bodies are size capped, and only the models and fields the app uses are forwarded. A Durable Object ledger caps hosted Reactor sessions at two per visitor and five in all, each ended after ten minutes. The `HOSTED` var turns every hosted route off at once.
- **Daily budget.** A second Durable Object meters hosted spend per UTC day: agent tokens in and out, generated images and sounds, element calls, and Reactor session-seconds, each against a ceiling set in `deploy/wrangler.jsonc`. A single /24 or IPv6 /48 gets its own token ceiling, a tenth of the whole, so one scripted client cannot drain the day. Past a ceiling, that route answers 503 until midnight UTC; play on your own keys is never metered. The owner reads the day's usage at `/api/budget` with a secret header.
- **Your own keys are optional.** Keys saved through **Use your own keys** stay in that browser's local storage and go only to their own provider; Jev's requests pass through the page's `/jev` route with the visitor's key. The Reactor key is exchanged in the browser for short-lived, session-scoped tokens. The page's only third-party script and frame are Turnstile's, and its Content Security Policy lets it connect only to its own origin and the providers it uses.
- **Shared worlds.** A world shared by link is stored on the Worker as its text only (premise, world and busy state), capped in size, for 180 days, with nothing about who wrote it.
- **Development and release.** The dev server fills empty key fields from `.env.local`, only for loopback requests, and its dev endpoints refuse other sites' requests; it never serves `.env*`, `.agent` or `.claude`, and git ignores them. `pnpm check` builds the app and fails if any `.env.local` value appears in the bundle, and the deploy script sets the Worker's secrets from `.env.local`, with a fresh pass-signing secret, through wrangler's standard input without printing them.

## Reporting a vulnerability

Please report a vulnerability privately through this repository's security advisories on GitHub ("Report a vulnerability" on the Security tab), not in a public issue. Include the steps to reproduce it and what an attacker could reach.
